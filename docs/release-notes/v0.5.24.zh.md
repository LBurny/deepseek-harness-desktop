# 中文说明

[← 返回 v0.5.24 发布页](https://github.com/LBurny/deepseek-harness-desktop-releases/releases/tag/v0.5.24) | [English](https://github.com/LBurny/deepseek-harness-desktop-releases/releases/tag/v0.5.24)

本版一项修复：远程隧道传输层从 QUIC 换成 HTTP/2，消灭"会话明明正常、隧道唯一连接却在底下烂掉"这一类断流。运行时与会话格式不变，覆盖安装即可。

### 1. 远程访问：隧道传输层钉死 HTTP/2

本机 41 天事件日志取证：18 次 `timeout: no recent network activity`（整条 QUIC 连接空闲后腐烂）+ 12 次 QUIC 拨号失败。QUIC 走 UDP，而运营商/校园网会激进回收空闲 UDP 流——一旦命中，隧道的唯一边缘连接死亡，所有在途长连接（`/plugins/events` 的 SSE、remote.mux 的 WebSocket）被边缘连带取消。quick tunnel 锁死单连接（`--ha-connections` 对它无效、传了会被静默忽略），没有冗余可兜底；0.5.22 加的应用层保活也救不了已死的传输层。

隧道启动参数现在钉死 `--protocol http2`：TCP 传输自带 keepalive，不受 UDP 空闲回收影响，这也是 Cloudflare 官方对"空闲长连接掉线"的建议对策。本机实测注册正常（边缘分配 hkg09）。代价只是放弃 QUIC 的 0-RTT 握手，对长驻隧道无感。

### 2. 兼容性

运行时与会话格式不变，会话、MCP 配置、技能、主题与语言选择全部原样保留。Rust 全量测试通过（294 条，0 失败），含新增的隧道传输层锚定测试（防止协议静默回退到 QUIC）。
