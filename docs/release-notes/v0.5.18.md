This release fixes the mobile session header, where the conversation title vanished and the mode, background-task and open-in-app controls piled on top of each other. The cause was upstream layout, not the shell: the header has no narrow-width adaptation at all. Nothing else changes: a normal in-place update is enough, and your sessions, MCP servers, skills and choices are untouched. On a phone, reload the page once to pick the fix up.

### 1. What was wrong

Measured on a real narrow viewport (390px, temporary dsh instance plus a browser driven by Playwright), the header row put its title at **0 pixels wide**: the session name was completely invisible, and the only place it still appeared was the phone browser's own title bar. Two of the three trailing groups are declared `flex: none`, so they never give up space, while the title's breadcrumb is `min-width: 0` and collapses first. With the mode pill (68px) and, in a session that has background jobs, the job pill (101px) in the same row, the action group's content grew to 177px inside a box that could not hold it, and the pills ended up **overlapping the right-hand buttons by 9px**. That is the "squeezed together" screenshot.

### 2. The fix

The mobile stylesheet keeps only the elasticity, and hides nothing. Title, mode and background-task pills each get a floor of `min(px, vw)` and are allowed to shrink, so none of them can be squeezed out of existence, and on very narrow phones the floors step down with the viewport so nothing overlaps even at 320px. The mode pill needed one extra step: its text is an anonymous flex item inside the pill, so the `text-overflow` on the pill itself does nothing (the stock `max-width: 180px` only hard-clips it), and the pill is now an `inline-block` so the ellipsis really renders, with its icon explicitly turned back into an inline box so the 22px pill does not become two lines tall. The background-task and schedule pills (both share the same three class names) get an ellipsis on their count and a width ceiling tied to their container, so "4 background jobs" becomes "4 ..." instead of pushing the title out. Finally the header's own left and right padding drop from 20/28 to 12/12, with the corner button's negative margin compensated, which hands 24px to the title while the right-hand toggle stays exactly 12px from the screen edge.

### 3. Verification

Nine widths were measured (320, 360, 375, 390, 414, 500, 600, 700, 720): the gap inside the row is 12px at every one of them, the row never overflows, and the header stays 76px tall. At 600px and above all three items return to their full native form, and at 701px and above none of the rules apply, so the desktop shell and a wide remote window are pixel-identical to before. The full Rust suite passes (306 tests, 0 failures), including a new rule-level regression test and six targeted contract probes for the header anchors.

### 4. Compatibility

No runtime version change, no session format change, no configuration change. Updating in place is enough.
