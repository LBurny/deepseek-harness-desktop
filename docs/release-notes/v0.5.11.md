This release fixes the "Failed to load plugins" error that could appear after configuring an MCP server, and makes the main window able to heal itself when a page fails to load. It also adds better logging and a diagnosis switch for future issues.

### 1. Fixed: "Failed to load plugins" after configuring MCP

Every time the dsh service restarts, it issues a login cookie with a brand-new name, and the window's cookie jar kept all of them (66 were found on a real machine). After enough restarts, web requests carried too many cookies plus a very long plugin bundle URL, exceeded the server's request header limit, and the server rejected the whole bundle with HTTP 431. That is what "Failed to load plugins" was.

The shell now clears those stale cookies before opening the UI, every time, so the jar stays at a single fresh cookie. Restarting dsh no longer accumulates anything. Remote access from the phone was never affected. If you connected to dsh directly from your own browser (for example Chrome), clear its cookies for 127.0.0.1 once.

### 2. New: automatic self-healing for a stuck page

If the main window has not finished loading 30 seconds after the service is ready, the shell now clears the cookies and reloads the page once by itself. No manual "restart and hope" needed.

### 3. New: page errors are now recorded

JavaScript errors and failed resource loads inside the UI now land in events.log (rate-limited, login tokens redacted), together with a `dsh UI booted (Xs)` line on every successful load. Problems like this one used to leave no trace in the log at all; now the first evidence is there.

### 4. New: deep diagnosis switch

Create an empty file named `debug-cdp` in `%LOCALAPPDATA%\DSHDesktop` and restart the app: the window's engine opens a debugging port on 9222 that browser DevTools can attach to. This is exactly how the cause above was found. Remove the file when finished; the port exposes page content to local processes, so only keep it while debugging.

### 5. Larger request header limit for the built-in server

The bundled dsh server now accepts request headers up to 64 KB (previously 16 KB). This is a second line of defense behind the cookie cleanup and also covers connecting your own browser directly to dsh.
