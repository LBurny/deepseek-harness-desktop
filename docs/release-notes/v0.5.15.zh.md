# 中文说明

[← 返回 v0.5.15 发布页](https://github.com/LBurny/deepseek-harness-desktop-releases/releases/tag/v0.5.15) | [English](https://github.com/LBurny/deepseek-harness-desktop-releases/releases/tag/v0.5.15)

本版大幅缩短配置了 MCP 集成时的启动等待，并让会话头部的「打开方式」按钮即刻出现。内嵌的 DeepSeek Harness 运行时不变，会话数据不受影响，按正常覆盖安装升级即可。

### 1. 修复：配置 MCP 服务后启动长时间卡在「正在准备运行时…」

装了 MCP 集成（比如 Context7、Playwright）后，启动可能卡在「正在准备运行时…」半分钟甚至更久才见到界面。根因：内嵌 harness 有意等全部插件就绪后才宣布自己可以接待，而用浮动包名配置的 MCP 服务（npx 未钉版本）每次启动都要向 registry 做一次网络往返，首次冷装更是要数分钟，这段等待此前全额叠进了启动。现在壳在启动时调整这一行为：默认配置下 MCP 连接转到后台进行，不再卡住就绪信号。真机实测（装有两个 MCP 服务）：启动从 36.6 秒降到约 5 秒。需要知道的代价：界面打开后的最初几秒，MCP 工具可能还在连接中，各服务一连上就会自动注册，稍等即可。如果你显式把某个 MCP 服务设为「启动失败即整体失败」，该严格行为原样保留。

### 2. 修复：会话头部「打开方式」按钮比其它按钮晚出现

「打开方式」按钮（VS Code / 文件资源管理器）此前总比头部其它按钮晚两三秒才冒出来——界面要先等一轮「本机装了哪些应用」的探测才肯画它，而这轮探测是每次启动才懒做一次（冷约 2.9 秒）。现在探测结果会缓存在浏览器存储里，按钮第一帧就按缓存渲染；新一轮探测完成后如果发现有变化再静默校正。本次升级后的第一次启动仍是原来的节奏（还没有缓存），之后每次启动都是即时出现。卸载过的应用条目可能短暂残留，待新探测落地后自动消失。
