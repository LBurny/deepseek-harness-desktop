This release fixes an environment-level plugin install failure: installing or updating a plugin on dsh's plugin page failed with `ERR_PNPM_UNEXPECTED_STORE` (Unexpected store location), and restarting the app did not help. The shell now detects and repairs this store drift automatically on every launch. No runtime or session format change; update in place and the repair runs on the first start.

### 1. What was wrong

A profile's dependency tree (`node_modules`) is linked against the pnpm store **from when it was created** (the store path is recorded in `node_modules/.modules.yaml`), while the pnpm that actually runs installs resolves its store from your machine's **global configuration**. Once the two drift apart — most commonly because you moved the global pnpm store to another drive, or a pnpm upgrade changed the default store location — every install or update against the old tree is rejected with `ERR_PNPM_UNEXPECTED_STORE`, with no self-service way out: restarting the app or reopening the plugin page changes nothing, and the only manual fix was deleting the whole dependency tree. Confirmed on a machine whose global store moved to a different drive on Sep 21: the first plugin install on a profile created in early September failed immediately.

### 2. The fix: detect and relink on launch

Before each dsh launch the shell now compares the store path recorded in the dependency tree with the one the bundled pnpm actually resolves to. On a mismatch it repairs automatically: the old tree is renamed aside, dependencies are relinked from the new store per the manifest and lockfile (missing packages are downloaded from npm), and the backup is removed on success. If the relink fails or times out (5-minute budget), the rename is rolled back and the old tree stays exactly as it was — dsh keeps running as before, and installs simply keep their old error rather than getting worse. Everything is logged to the diagnostics log (events.log) with no popups; machines that never customized their store detect a match and pass through at zero cost. When the first launch after the upgrade logs `pnpm store heal: Healed { .. }`, the repair is done — just retry the install on dsh's plugin page.

### 3. Compatibility

No runtime or session format change. Sessions, MCP servers, skills and theme/language choices are all preserved. The plugin panel stays retired as of 0.5.21 (installs go through dsh's own plugin page). The full Rust suite passes (284 tests, 0 failures), including a new flow-level regression for the store heal covering all four states: match (no action), migrate (relink), failure (rollback), and fresh profile (skip).
