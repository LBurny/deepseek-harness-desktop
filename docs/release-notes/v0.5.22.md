This release has four fixes and one component update: plugin installs now self-repair when the pnpm store drifts (`ERR_PNPM_UNEXPECTED_STORE`), remote connections are no longer silently dropped by Cloudflare after roughly two minutes of idle, the remote tunnel no longer gives up permanently after repeated startup failures, and dsh's plugin page header no longer breaks at narrow mobile widths. The bundled cloudflared is updated to 2026.9.3. No runtime or session format change; update in place.

### 1. Plugin install failure: automatic store repair

Installing or updating a plugin on dsh's plugin page failed with `ERR_PNPM_UNEXPECTED_STORE` (Unexpected store location), and restarting the app did not help.

A profile's dependency tree (`node_modules`) is linked against the pnpm store **from when it was created** (the store path is recorded in `node_modules/.modules.yaml`), while the pnpm that actually runs installs resolves its store from your machine's **global configuration**. Once the two drift apart — most commonly because you moved the global pnpm store to another drive, or a pnpm upgrade changed the default store location — every install or update against the old tree is rejected, with no self-service way out: restarting the app or reopening the plugin page changes nothing, and the only manual fix was deleting the whole dependency tree. Confirmed on a machine whose global store moved to a different drive on Sep 21: the first plugin install on a profile created in early September failed immediately.

The shell now compares the store path recorded in the dependency tree with the one the bundled pnpm actually resolves to before each launch, and repairs automatically on a mismatch: the old tree is renamed aside, dependencies are relinked from the new store per the manifest and lockfile (missing packages are downloaded from npm), and the backup is removed on success. If the relink fails or times out (5-minute budget), the rename is rolled back and the old tree stays exactly as it was — dsh keeps running as before, and installs simply keep their old error rather than getting worse. Everything is logged to the diagnostics log (events.log); machines that never customized their store pass through at zero cost. When the first launch after the upgrade logs `pnpm store heal: Healed { .. }`, the repair is done — just retry the install on dsh's plugin page.

### 2. Remote: no more "brief disconnect" while the page sits idle

The events log showed dsh's server-sent event stream being cut by the Cloudflare edge every 88-97 seconds (278 "stream canceled by remote" entries in one week): Cloudflare kills idle connections after roughly a 100-second window, and a quick tunnel with both ends silent gets reclaimed — the main WebSocket data channel lives in the same window, which is why a phone left alone for two minutes would visibly "disconnect and reconnect".

The fix is idle-triggered keepalive in the shell's proxy, so an active channel sends nothing at all: after 30 seconds of upstream silence the proxy sends an empty WebSocket ping to the browser (the browser replies automatically at the protocol level, which also keeps the tunnel's reverse direction warm), and after 30 seconds of upstream silence on any server-sent event stream the proxy injects a `: keepalive` comment line (valid per the SSE spec and invisible to the EventSource client). dsh itself is unchanged. If "stream canceled" lines ever reappear in the log, that is the signal to investigate.

### 3. Remote tunnel: no more permanent give-up after repeated failures

Previously, five consecutive failed starts (exponential backoff 500ms to 30s, about two minutes total) put the tunnel into a permanent Failed state — a slow first cloudflared download or a longer network hiccup left remote access dead until you toggled it manually. Now, after the five quick attempts the Failed state stays visible but supervision degrades to one slow retry every 5 minutes, indefinitely; any success resets supervision back to normal. Stopping the tunnel still takes effect immediately during the slow wait.

### 4. Mobile: plugin page header no longer squashed

On dsh's own plugin page the header is a single-row flex with no narrow-screen adaptation anywhere in the package: at 390px the "Add plugin" button's text wrapped into two lines and the intro description wrapped, leaving the info icon orphaned on its own line. The fix keeps every control and only adjusts flex behavior: the button never wraps its text, the tool group refuses to shrink, the title group is allowed to shrink, and the intro becomes a single ellipsized line (the full text is in the info tooltip, so nothing is lost). Verified against a real dsh 0.2.0-rc.1 instance at 390px.

### 5. Compatibility

No runtime or session format change. Sessions, MCP servers, skills and theme/language choices are all preserved. The bundled cloudflared is updated to 2026.9.3 and takes effect on the next cold start of the tunnel without disturbing a running one. The plugin panel stays retired as of 0.5.21 (installs go through dsh's own plugin page). The full Rust suite passes (291 tests, 0 failures), including new regressions for the store heal, the keepalive injection, and the tunnel retry downgrade.
