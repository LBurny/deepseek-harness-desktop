This release has one fix: the remote tunnel's transport is switched from QUIC to HTTP/2, eliminating a class of drops where the tunnel's only edge connection rotted away underneath an otherwise healthy session. No runtime or session format change; update in place.

### 1. Remote access: tunnel transport pinned to HTTP/2

Evidence from 41 days of the local event log: 18 "timeout: no recent network activity" failures where the whole QUIC connection rotted after going idle, plus 12 QUIC dial failures. QUIC runs over UDP, and carrier/campus networks aggressively recycle idle UDP flows — when that happens, the tunnel's single edge connection dies and every in-flight long-lived stream (the `/plugins/events` SSE feed, the remote.mux WebSocket) gets cancelled by the edge. Quick tunnels are locked to one edge connection (`--ha-connections` is silently ignored for them), so there is no redundancy to absorb the hit, and the application-level keepalive added in 0.5.22 cannot rescue a dead transport.

The tunnel now launches with `--protocol http2`: TCP transport with its own keepalive, unaffected by UDP idle recycling, and also Cloudflare's officially recommended remedy for idle long-lived connection drops. Verified live from this machine: registration succeeds normally (edge assigned hkg09). The only trade-off is losing QUIC's 0-RTT handshake, which a long-lived tunnel never notices.

### 2. Compatibility

No runtime or session format change. Sessions, MCP servers, skills and theme/language choices are all preserved. The full Rust suite passes (294 tests, 0 failures), including a new anchor test that pins the tunnel transport so it cannot silently regress to QUIC.
