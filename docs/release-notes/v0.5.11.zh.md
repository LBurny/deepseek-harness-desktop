# 中文说明

[← 返回 v0.5.11 发布页](https://github.com/LBurny/deepseek-harness-desktop-releases/releases/tag/v0.5.11) | [English](https://github.com/LBurny/deepseek-harness-desktop-releases/releases/tag/v0.5.11)

本次更新修复"配置 MCP 后主窗口报 Failed to load plugins"的问题，主窗口页面加载失败时还会自动自愈，并为以后的排障加了新的日志与诊断开关。

### 1. 修复：配置 MCP 后主窗口 "Failed to load plugins"

dsh 服务每次重启都会发一个**新名字**的登录 cookie，窗口的 cookie 罐只进不出（实机抓到攒了 66 个）。攒够之后，请求头带着这些 cookie 加上一条很长的插件脚本地址，超过服务器请求头上限，整包脚本被拒（HTTP 431），主窗口就报 "Failed to load plugins"；重启 dsh 也没用，罐子只会更满。

现在壳每次打开界面都先清掉这些陈年 cookie，罐子里始终只有一个新 cookie，重启多少次都不再累积。手机远程访问从不受影响。如果你用自己的浏览器（比如 Chrome）直连过 dsh，请把浏览器里 127.0.0.1 的 cookie 清一次。

### 2. 新增：页面卡住自动自愈

服务就绪后 30 秒页面还没加载完成，壳会自动清 cookie 并凭据重载一次，不用再手动重启碰运气。

### 3. 新增：页面报错进入日志

内置界面的 JS 报错、资源加载失败现在会限流写入 events.log（登录凭据自动脱敏），每次成功加载也会落一行 `dsh UI booted (Xs)`。这类问题以前在日志里毫无痕迹，现在第一时间有案底。

### 4. 新增：深度诊断开关

在 `%LOCALAPPDATA%\DSHDesktop` 放一个名为 `debug-cdp` 的空文件并重启应用，窗口内核会开启 9222 调试端口，可用浏览器 DevTools 直连查看网络层——本次问题的根因就是这么定位的。排障完把文件删掉即可（该端口会把页面内容暴露给本机进程，勿常开）。

### 5. 内置服务的请求头上限提高到 64KB

原上限 16KB。这是 cookie 清理之外的第二道保险，也覆盖用自己浏览器直连 dsh 端口的场景。
