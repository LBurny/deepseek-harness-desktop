dsh 0.2.0 ships its own full plugin manager page (install, configure, enable/disable, runtime uninstall, with official/mirror/custom sources), which made the shell's own plugin panel a duplicate maintenance surface. As decided, this release retires it entirely: the tray no longer has a "Plugins" item, and the in-shell page plus its backing commands are gone. Manage plugins directly in dsh's plugin page. No runtime or session format change; update in place.

### 1. What changed

- The tray menu no longer has "Plugins"; the shell no longer ships a plugin page, window or the commands behind them.
- dsh's plugin page covers the same ground and more: official optional plugins, installed plugins (including our /init, now with a bilingual description), install-source selection, runtime enable/disable and uninstall.
- The built-in /init seeding and guarding logic is unchanged: upgrades still sync its files, and uninstalling it from dsh's plugin page still keeps it removed (the "user removed it, don't resurrect" behavior is untouched).

### 2. What didn't change

Skills, MCP, remote access, diagnostics and settings tray items are all untouched, as are your sessions, MCP servers, skills and theme/language choices. MCP management is intentionally out of scope for this retirement (the shell edits underlying patch files beyond dsh's panel; we will revisit as dsh's panel coverage grows). The full Rust suite passes (283 tests, 0 failures) and the frontend build is clean.
