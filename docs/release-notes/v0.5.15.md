This release cuts startup time sharply when MCP integrations are configured, and makes the "Open with" button in the session header appear instantly. The bundled DeepSeek Harness runtime is unchanged, and no session data is affected - a normal in-place update is enough.

### 1. Fixed: long stall on "Preparing runtime..." when MCP servers are configured

With MCP integrations added (for example Context7 or Playwright), the app could sit on the splash screen for half a minute or more before the interface appeared. The cause: the embedded harness deliberately waits for all plugins to settle before declaring itself ready, and every MCP server configured with a floating package name (npx without a pinned version) makes a network round trip to the registry on every launch - a first-time install can take minutes - and that whole wait was added to startup. The desktop shell now adjusts this behavior at launch: with the default configuration, MCP connections continue in the background instead of holding up the ready signal. Measured on a real machine with two MCP servers: startup dropped from 36.6 seconds to about 5 seconds. One trade-off to know: in the first few seconds after the interface opens, MCP tools may still be connecting; each server registers its tools automatically as soon as it is up. If you explicitly configured an MCP server to fail the whole startup on error, that strict behavior is preserved unchanged.

### 2. Fixed: "Open with" button in the session header appears later than everything else

The "Open with" button (VS Code / File Explorer) used to pop in two or three seconds after the rest of the session header, because the interface waited for a fresh "which apps are installed on this PC" scan before drawing it, and that scan runs lazily once per launch (about 2.9 seconds cold). The scan result is now cached in browser storage, so the button renders from the cache on the very first frame; once the fresh scan finishes, the list quietly corrects itself if anything changed. The first launch after this update still runs at the old pace (no cache yet); every launch after that is instant. If you uninstall an app, its entry may linger until the fresh scan lands, then disappears on its own.
