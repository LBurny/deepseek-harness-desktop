# 中文说明

[← 返回 v0.5.22 发布页](https://github.com/LBurny/deepseek-harness-desktop-releases/releases/tag/v0.5.22) | [English](https://github.com/LBurny/deepseek-harness-desktop-releases/releases/tag/v0.5.22)

本版修一个插件安装的环境级故障：在 dsh 插件页安装/更新插件时报 `ERR_PNPM_UNEXPECTED_STORE`（Unexpected store location），重启应用也无效。壳现在会在每次启动时自动检测并修复这种 store 漂移，装包恢复可用。运行时与会话格式不变，覆盖安装即可，升级后首次启动自动完成修复。

### 1. 问题出在哪

插件的依赖树（profile 的 `node_modules`）链接在**创建它时**的 pnpm store（`node_modules/.modules.yaml` 里记录了当时的 store 路径），而每次实际执行安装的 pnpm 按你机器上的**全局配置**解析 store。两者一旦漂移——最常见的就是把 pnpm 全局 store 迁到另一个盘，或 pnpm 升级改变了默认 store 位置——对旧依赖树的任何安装/更新操作都会被 pnpm 直接拒绝，报 `ERR_PNPM_UNEXPECTED_STORE`，且没有自助出口：重启、重开插件页都没用，只能手工删掉整个依赖树重装。实锤场景：9 月 21 日把全局 store 迁到 F 盘后，9 月初建立的 profile 首次装插件即报错。

### 2. 修法：启动时自动检测并重链

壳现在每次启动 dsh 前做一次检测：读依赖树记录的 store 路径，与内置 pnpm 实际解析到的 store 比对；不一致时自动修复——把旧依赖树改名备用 → 按清单和 lockfile 从新 store 重新链接（缺的包会从 npm 源下载）→ 成功后清掉备用。重链失败或超时（5 分钟预算）则回滚改名，旧依赖树原样保留——dsh 照常可跑，只是装包维持原报错，不会更糟。全程只在诊断日志（events.log）留痕，不弹任何提示；从没自定义过 store 的机器检测到一致、零开销通过。升级后首次启动日志里出现 `pnpm store heal: Healed { .. }` 即为修复完成，之后在 dsh 插件页重新安装即可。

### 3. 兼容性

运行时与会话格式不变，会话、MCP 配置、技能、主题与语言选择全部原样保留。插件面板维持 0.5.21 的退役状态（装插件走 dsh 自己的插件页）。Rust 全量测试通过（284 条，0 失败），新增 store 迁移自愈的流程级回归（一致不动作 / 迁移重链 / 失败回滚 / 首启跳过四态）。
