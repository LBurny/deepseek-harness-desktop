# 中文说明

[← 返回 v0.5.17 发布页](https://github.com/LBurny/deepseek-harness-desktop-releases/releases/tag/v0.5.17) | [English](https://github.com/LBurny/deepseek-harness-desktop-releases/releases/tag/v0.5.17)

本版修好两个"点了没反应"的文件卡片菜单项：「在文件资源管理器中显示」与「打开所在文件夹」现在会真的弹出资源管理器窗口，并选中对应文件。根因在上游而非壳，且凡是在 Windows 上跑 dsh 的都会中招，所以壳侧新增了一枚签名门控补丁。其余一切不变：按正常覆盖安装升级即可，会话、MCP 配置、技能与各项选择都原样保留。

### 1. 问题出在哪

reveal 其实一直在正常执行。dsh 的原生命令运行器对所有宿主机命令一律带 windowsHide 起子进程，而这在 Windows 上等于给子进程置上 SW_HIDE；资源管理器的文件夹窗口走 SW_SHOWDEFAULT，于是继承了这份隐藏态——窗口确实建在正确目录、也选中了正确文件，但它是"不可见地"创建出来的。host 路由照常回 204，卡片因此显示"已请求"，桌面却什么都不弹，症状就是"点了没反应"。

两条证据都来自反馈机器本身。它的桌面上已经积了 4 个不可见的资源管理器窗口，位置正是交付文件所在目录、每个都选中了那个文件，说明点击从头到尾都执行到了 OS 层，只有"可见"这一步丢了；以及在真实生产模块上做的单变量对照——同一条调用，windowsHide 为 true 时 IsWindowVisible=false，置 false 或省略即为 true。上游尚未修复：npm 上最新的 alpha 里那一行仍是 `windowsHide: true`，跟版解决不了。

### 2. 修法

新增 revealshow.rs：与既有四枚同款的启动期原地补丁（签名门控、marker 幂等、tmp+rename 原子写、漂移即停手），只把 explorer.exe 从该选项里豁免出去——对它 windowsHide 变 false，其余命令照旧 true。豁免范围刻意收窄：「用默认应用打开」背后的 powershell 路径实测即使 windowsHide 打开也可见（它经 ShellExecute 把请求交给已在运行的桌面 explorer），而控制台应用的控制台窗口必须保持隐藏——壳"不闪控制台"的硬规则不受影响。PE 头核实这个分工是安全的：explorer.exe 是 GUI 子系统（2），本来就不可能创建控制台；powershell.exe / taskkill.exe 才是控制台子系统（3）。

### 3. 验证

Rust 全量测试通过（305 条，0 失败），含对真实运行时的上游契约套件（现在也盯住这枚补丁的签名）。端到端验证直接 import 由真实 Rust 补丁改写出的模块、调菜单用的那个函数：未打补丁的副本产出不可见窗口，打过补丁的产出可见窗口且选中正确文件。安装包内附的运行时在磁盘上保持原样，补丁在启动时施加，dsh 自更新还原文件后下次启动会重打。

### 4. 兼容性

运行时版本不变、会话格式不变、配置不变。覆盖安装即可。
