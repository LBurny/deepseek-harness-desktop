This release fixes three reports: the dark theme no longer applying at startup (a 0.5.19 shell regression, now fixed at the root), the mobile context-usage ring moving into the Info page, and the built-in /init plugin gaining a bilingual description. The runtime is unchanged (still 0.2.0-rc.1), the session format is unchanged (V4), and a normal in-place update is enough.

### 1. Dark theme at startup now applies correctly

With 0.5.19, dsh 0.2.0 turned the flat `settings.yaml` into a one-shot migration channel (imported into the new store and renamed on every launch), while the shell kept recreating that file at every start — so the imported stale value overwrote the theme you picked in the app, which looked like "the UI stays light in dark mode, but restarting the service fixes it". The shell now uses dsh 0.2.0's real settings store (the settings entries in the profile patch): the title bar theme and the shell language follow your in-app choice live, with no per-launch overwrite loop. The first-launch theme seeding is retired too — since 0.2.0 both sides default to "follow system", so the first launch is consistent by itself. No action needed; your theme and language choices are preserved.

### 2. Mobile: the context-usage ring moves into the Info page

The context-usage ring that 0.2.0 added under the composer ("○ 26%") occupied its own line on a phone. It now receives the same treatment as the turn-stats row: it lives in the Info page above the stats breakdown, and no longer hangs under the input box. It only appears when usage data exists, updates live, and — like the stats row — is a read-only display there (the detailed breakdown panel remains available by clicking the ring on desktop).

### 3. The /init plugin has a description now

Our /init plugin was the only one in the plugin manager without a description. Following upstream's plugin metadata mechanism it now ships Chinese and English text: the Chinese UI shows 「初始化命令——创建或更新当前工作区的 AGENTS.md 指令文件…」, the English UI the matching English line, switching instantly with the interface language. Existing installs pick it up automatically through the shell's plugin file sync; no reinstall or re-enable needed.

### 4. Compatibility

No runtime or session format change. Your theme and language choices, sessions, MCP servers and skills are all preserved; update in place. The `settings.yaml.imported` leftover from 0.5.19 is harmless and no longer read or written. The full Rust suite passes (290 tests, 0 failures), including the contract suite against the real runtime, now with five new settings-store probes.
